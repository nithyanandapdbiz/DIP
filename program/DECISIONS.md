## 2. Decisions derived from legacy failure analysis

Each is a **mechanism**, not an intention. Each maps to a specific, evidenced failure in the predecessor.

| # | Decision | The failure it prevents | Status |
|---|---|---|---|
| **D-011** | **Defaults are architecture.** A feature flag may protect a *rollback* path from the conformant default. It may never protect the *conformant* path from a non-conformant default. | The predecessor's single most consequential contradiction: the conformant orchestration path was fully built and working, but required an opt-in environment variable — so the non-conformant path was what every deployment actually ran. The same pattern recurred on three further flags. | ACCEPTED |
| **D-012** | **Declaration and enforcement are one atomic change.** Adding a configuration field requires, in the same change, the enforcing code and a test proving enforcement. Preferred form: derive the schema from registered readers, so an unenforced field is *unrepresentable*. | A retention limit was customer-visible, schema-validated, API-served and console-rendered — and read by no code. Six of eight declared limit fields had no reader. Schema validation validated the *shape* of the value, which manufactured the appearance of a live control. | ACCEPTED |
| **D-013** | **Fail loudly by default.** Soft failure is an explicit per-call-site opt-in; in a security capability it additionally requires an ADR. | A penetration-testing engine was tier-listed as enabled and exposed via API with no runner on disk. Its dispatch wrapper *logged* the missing script and returned a soft failure. A security capability that silently does nothing is indistinguishable from a clean result. | ACCEPTED |
| **D-014** | **Never share code by relative filesystem path.** Shared code is a versioned, owned, releasable package from the first commit. A directory reachable only by relative path is not a library. | A shared directory sat above both repository roots and therefore reached neither container image. It accumulated 26 import sites and 13 boundary-escaping files before the defect surfaced — because it only manifests at containerisation. | ACCEPTED |
| **D-015** | **Both images are built in CI on every commit**, and a build failure blocks merge. Build verification is never deferred to release. | An image was unbuildable for an extended period because a `COPY` referenced a directory deleted three commits earlier. The only build ran on release tags. | ACCEPTED |
| **D-016** | **All gates run on all branches. `NOT RUN` is a reported state and is treated as `FAIL`. Branch protection is defined as code, in the repository.** | Gates triggered on `main`/`develop` while development happened on feature branches. One of five workflows produced any signal where work occurred; an architecture fitness test had been failing for an extended period with nobody notified. The predecessor's own conclusion: *the highest-value action available is configuration, not engineering*. | ACCEPTED |
| **D-017** | **Every capability is exercised end-to-end in CI from the moment it is declared.** Tier definitions validate against a capability registry at configuration load; declaring a capability with no execution path fails at load. | No capability script was ever invoked by CI. Two capabilities were declared and sold with no execution path at all. | ACCEPTED |
| **D-018** | **Prefer structural impossibility to tests.** Where a rule can be made unviolatable, it is. A rule that cannot be violated needs no test. | The predecessor's control plane conformed to its "two deployables" rule *because nothing called the function that would have broken it* — not because anything prevented it. The dangerous function was exported. Conformance-because-nobody-called-it is not conformance. | ACCEPTED |
| **D-019** | **Controls behave identically in every environment.** No environment conditionals in constitutional guards; no image default may weaken a control. | A raw credential crossed the trust boundary outside production, and startup validation shipped disabled by image default — meaning that control ran in no deployed container. Non-production environments routinely hold real credentials and have weaker guards. | ACCEPTED |
| **D-020** | **Every constitutional rule is enforced by at least three independent mechanisms.** | The one rule the predecessor enforced three ways (boot guard + build fitness test + entrypoint ban) never drifted. Everything enforced by a single mechanism, or by prose, did. This is the strongest empirical correlation in the legacy estate. | ACCEPTED |
| **D-007** | **Exactly one implementation per governed term**, defined before any producer or consumer, with mandatory domain separation and an algorithm version on every record. | Two implementations of one hashing term produced divergent digests, so evidence written by one and verified by the other reported tampering on untampered records — proven by execution. A false tamper verdict is more corrosive than a missed detection: it trains operators to discount the control. | ACCEPTED |
| **D-021** | **Unavailability and refusal are structurally distinct types** in the cross-plane contract, not status codes interpreted at call sites. Unavailability degrades and continues; refusal halts. | A single early return conflated the two, so the Execution Plane aborted whenever the Intelligence Plane was unreachable — including for the two capabilities that require no inference at all. The predecessor's assessment: *the architecture is correct; one early return contradicts it.* | ACCEPTED |
| **D-022** | **Degraded state is a required structural field on every result**, not a log line. A degraded result is a distinct type that the certification interface refuses to accept. | An unlabelled degraded pass is worse than an outage: an outage is visible, whereas a silently degraded certification is a false assurance that propagates into release decisions. | ACCEPTED |
| **D-008** | **Every gate is observed to fail on a planted violation before it is trusted**, and the fault-injection proof is recorded. | A control that has never been seen to fail is indistinguishable from one that cannot fail. | ACCEPTED |
| **D-009** | **AI-enabled and AI-disabled paths are built together** from the first capability. AI generates content; deterministic code renders every decision. | Retrofitting AI-optionality is a rewrite. The predecessor's agent layer implemented AI independence thoroughly and consistently — and one control-flow path in the other plane discarded all of it. | ACCEPTED |

## 3. Prohibited decisions

Recorded so that convenience cannot later be mistaken for a determination. Several are inherited from the predecessor, which recorded them precisely because they were **live temptations** during its own certification.

| # | Prohibited | Because |
|---|---|---|
| **P-001** | Amending the architecture to accommodate an implementation that violates it | Inverts the purpose of architecture. The implementation changes. A finding, an outage, a deadline, or an implementation difficulty is not grounds for amendment. |
| **P-002** | Editing a red gate green | A gate's value is entirely in its ability to fail. Where a gate cannot be made green, it is left **red** and escalated. |
| **P-003** | Treating a declared-but-unbuilt control as a gap rather than a violation | Manufactures confidence instead of measuring it, and inverts the purpose of governance: every declared control would then require independent verification before it could be believed. |
| **P-004** | Giving any capability a bespoke architecture | Divergent capability architectures are what the capability model exists to prevent. |
| **P-005** | Making AI mandatory on any path | The platform must function correctly with AI disabled. |
| **P-006** | Allowing secret material to cross the plane boundary in any environment | Only credential *references* cross. Foundational to the Sovereign Split. |
| **P-007** | Permitting the Execution Plane to make certification decisions | Judgment belongs to the plane that reasons; evidence to the plane that executes. Certification may be *deferred*, never *delegated*. |
| **P-008** | Reordering the roadmap for schedule pressure | Reordering is permitted only when a dependency is found to be wrong. |
| **P-009** | Deleting a declared commitment to close a finding | Resolves drift by abandoning the commitment rather than honouring it — the register goes green and the customer is no better off. |
| **P-010** | Weakening any control to production-only | Protects the environment least likely to be attacked. |
| **P-011** | Exempting any tool or vendor from the adapter/SPI requirement | An exemption concedes a pattern that must be demonstrated once and then applied uniformly. The predecessor built one conformant adapter layer of eight and let a vendor reach its identity layer as a result. |
