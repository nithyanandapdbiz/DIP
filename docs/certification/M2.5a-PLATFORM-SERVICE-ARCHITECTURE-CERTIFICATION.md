## 3. Constitutional compliance

**R-11.4 holds unchanged.** The platform exposes exactly six Quality Engineering Capabilities. Documents 23–25 declare themselves **Platform Services** and are verified as such by a fitness function that reads each document's classification line.

**That check exists because the cardinality count cannot see this failure.** A Platform Service document declaring itself a capability would create a seventh under a different name while document 11 still counted six.

## 5. The coverage map: an input, not a measurement

Document-to-milestone mapping cannot be derived — nothing in an architecture document knows which milestone will build it. It is therefore a **declared input** in `coverage-map.json`, and the coverage computed from it is the measurement.

**It is not recorded inside the architecture documents deliberately.** A milestone stated in a frozen document would require amending frozen architecture every time the roadmap moved, which is precisely what a freeze prevents. Architecture states what shall be true; the programme states when it will be built.

**The input is still checked.** A coverage entry naming a milestone the programme plan does not define is reported as a phantom — otherwise the map would be a way to make the matrix green by pointing at nothing.
